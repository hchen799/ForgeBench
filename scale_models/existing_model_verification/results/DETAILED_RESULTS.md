# Production full-model results

The device under test in every row is saved C++ generated by the production
JSON -> `gen_configs.run_hls_flow` workflow. Each run uses seed 42 and compares
the C++ outputs with an independent fixed-point PyTorch graph and an FP64
PyTorch graph. Fixed acceptance requires zero differing codes. FP64 acceptance
requires relative L2 <= **5%** at every observed tensor.

| Model | Implementations | Q16.5 | Q16.5 logits rel. L2 | Q32.10 | Q32.10 logits rel. L2 |
|---|---|---|---:|---|---:|
| ResNet-18 | full + tiled | PASS | 0.511272% | PASS | 0.000191553% |
| ResNet-34 | full + tiled | PASS | 0.764899% | PASS | 0.000218755% |
| ResNet-50 | full + tiled | PASS | 1.241235% | PASS | 0.000507193% |
| ResNet-101 | full + tiled | PASS | 1.942698% | PASS | 0.000629521% |
| ResNet-152 | full + tiled | PASS | 2.046199% | PASS | 0.000612012% |
| Llama-3-8B ctx2048 | prefill + 2 decode | FAIL | 123.293%–125.028% | PASS | 0.000265945%–0.000306626% |
| Llama-3-8B ctx8192 | prefill + 2 decode | FAIL | 123.293%–125.028% | PASS | 0.000265945%–0.000306626% |

All full/tiled pairs produce identical measurements because they use identical
tensor-specific seeds and implement the same graph. Every row has exact C++ vs
fixed-PyTorch agreement. ResNet-152 Q16 has logits max absolute error 0.116542;
this remains in the report as a diagnostic and passes the requested 5% relative
L2 criterion.

The Llama campaigns execute the complete 32-layer, 8,030,261,248-parameter
graph with hidden size 4096, FFN size 14336, and vocabulary 128256. Each uses a
four-token prefill and two one-token decodes. Context 2048 and 8192 are cache
capacities, not executed prompt lengths. The generated ctx8192 C++ exposes and
writes the larger caches, while comparisons select all populated entries. The
same first six positions therefore produce the same numerical metrics.

The [combined JSON index](validation_summary.json) links all 24 reports and
records aggregate extrema and failed tensors. Per-run logs under
[`../logs/csim`](../logs/csim) include final-layer details. Q16 Llama failures
are retained rather than hidden by the Q32 pass.

[Expanded regeneration evidence](audits/expanded_regeneration.json) confirms
that the documented JSON workflow reproduced all five project files byte for
byte for 16 newly generated depth/context/precision projects.

These are C-simulation results with synthetic parameters. No pretrained-model
accuracy, 2048/8192-token prompt, full RTL, FPGA execution, timing, or
performance claim is made.
